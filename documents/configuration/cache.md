# 缓存配置

`cache` 配置块控制 Load Ants 内置的 DNS 缓存。缓存命中时直接返回结果，降低解析延迟，减少对上游服务器的请求。

缓存的工作原理详见 [**核心概念：高性能缓存机制**](../concepts/caching.md)。

### 示例

```yaml
cache:
    enabled: true
    max_size: 10000
    min_ttl: 60
    max_ttl: 3600
    negative_ttl: 300
```

> 📝 **注意**：上述示例中的 `min_ttl: 60` 与 `max_ttl: 3600` 为常用示例值而非默认值，各参数的默认值见下方“参数详解”表。

### 参数详解

| 参数           | 类型   | 描述                                                                                                                              | 默认值  | 是否必填                   |
| :------------- | :----- | :-------------------------------------------------------------------------------------------------------------------------------- | :------ | :------------------------- |
| `enabled`      | 布尔值 | 是否启用 DNS 缓存功能。将其设为 `false` 或直接移除整个 `cache` 配置块，均可禁用缓存。                                             | `true`  | **是**（若 `cache` 块存在） |
| `max_size`     | 整数   | 缓存中可以存储的最大条目数。当缓存达到此上限时，最老的条目会被移除，为新条目腾出空间。                                            | `10000` | **是**（若 `cache` 块存在） |
| `min_ttl`      | 整数   | 缓存 TTL 下限（秒）：当响应中的记录 TTL 低于该值时，会被提升到 `min_ttl`。                                                        | `1`     | **是**（若 `cache` 块存在） |
| `max_ttl`      | 整数   | 缓存 TTL 上限（秒）：写入缓存时，响应 TTL 会先被 `min_ttl` 抬升，再被 `max_ttl` 截断，实际缓存的 TTL 不会超过该值。               | `86400` | **是**（若 `cache` 块存在） |
| `negative_ttl` | 整数   | 负向缓存 TTL（秒）：用于缓存失败查询（例如 `NXDOMAIN` 或无答案响应），可减少对无效域名的重复请求。                                | `300`   | **是**（若 `cache` 块存在） |
| `stale_while_revalidate` | 整数 | 过期缓存宽限时间（秒），有效范围 `0-86400`。大于 `0` 时，条目过期但未超出宽限期的请求会先返回过期缓存，并触发后台异步刷新；`0` 表示禁用。 | `0`     | 否                         |

> ✨ **专家提示**：
>
> - 家庭或个人用户可以直接使用默认的缓存配置，无需修改。
> - 如果你访问的服务 IP 地址经常变更，推荐通过路由或上游策略控制解析结果的更新节奏，也可以调低 `max_ttl` 缩短缓存时长。
> - 如果你的网络中有设备（例如 IoT 设备）频繁查询不存在的域名，可以调高 `negative_ttl` 来减轻上游服务器的压力。
