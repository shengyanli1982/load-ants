# 服务端配置

以下配置决定 Load Ants 如何对外提供服务：`server` 块定义接收 DNS 请求的监听地址与参数，`admin` 块定义管理与监控服务的监听地址。

### `server` 配置

`server` 配置块定义核心的 DNS 服务监听器。

#### 示例

```yaml
server:
    listen_udp: "0.0.0.0:53"
    listen_tcp: "0.0.0.0:53"
    listen_http: "0.0.0.0:8080"
    tcp_timeout: 10
    http_timeout: 30
```

#### 参数详解

绑定 53 等特权端口需要管理员权限。

| 参数           | 类型   | 描述                                                                                               | 默认值 | 是否必填 |
| :------------- | :----- | :------------------------------------------------------------------------------------------------- | :----- | :------- |
| `listen_udp`   | 字符串 | DNS over UDP 服务的监听地址和端口。`0.0.0.0` 表示监听本机所有网络接口。                            | `127.0.0.1:53`     | **是**   |
| `listen_tcp`   | 字符串 | DNS over TCP 服务的监听地址和端口。                                                                | `127.0.0.1:53`     | **是**   |
| `listen_http`  | 字符串 | （可选）内置 DoH（DNS over HTTPS）服务端监听地址和端口。配置后将启动 DoH 服务端；**若不配置，则不会启动 DoH 服务**。 | （不启用）         | 否       |
| `tcp_timeout`  | 整数   | TCP 连接空闲超时（秒），有效范围 `1-65535`。                                                       | `10`               | 否       |
| `http_timeout` | 整数   | DoH 服务端的 HTTP 连接空闲超时（秒），有效范围 `1-65535`。                                         | `30`               | 否       |
| `tls_cert`     | 字符串 | （可选）TLS 证书文件路径。与 `tls_key` 成对配置后，DoH 入站启用 HTTPS。                            | （不启用）         | 否       |
| `tls_key`      | 字符串 | （可选）TLS 私钥文件路径。与 `tls_cert` 成对配置后生效。                                           | （不启用）         | 否       |
| `rate_limit`   | 对象   | （可选）请求限流：`max_requests_per_second`（全局上限，块内必填）与 `per_ip_max_requests_per_second`（单 IP 上限，默认 `100`），有效范围均为 `1-100000`；不配置则不限流。 | （不限流）         | 否       |
| `udp`          | 对象   | （可选）UDP socket 配置：`recv_buffer` / `send_buffer`（缓冲区大小，字节，默认均为 `4194304` 即 4MB）与 `socket_count`（socket 数量，有效范围 `1-256`，默认 `1`；大于 `1` 时通过 `SO_REUSEPORT` 多 socket 绑定同一端口）。 | （默认值）         | 否       |

### `admin` Admin 服务器

`admin` 配置块定义一个独立的 HTTP 服务器，专门用于运维和监控。

> **重要**：当前版本中，`admin` 服务会在启动时创建并运行。
>
> - 若你在配置文件中提供 `admin` 块，则使用其 `listen`。
> - 若未提供 `admin` 块，则会使用默认监听地址 `127.0.0.1:9000`（仅本机可访问）。

#### 示例

```yaml
admin:
    listen: "0.0.0.0:9000"
```

#### 参数详解

| 参数     | 类型   | 描述                                                                                                                                                                                  | 默认值           | 是否必填 |
| :------- | :----- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :--------------- | :------- |
| `listen` | 字符串 | Admin 服务器的监听地址和端口。Admin 服务器暴露 `/health/live`（存活探针）、`/health/ready`（就绪探针）、`/metrics`（Prometheus 指标）以及 `/api/*` 运维端点（完整列表见下方）。建议将其配置在与主服务不同的端口上。 | `127.0.0.1:9000` | **是**   |
| `auth`   | 对象   | （可选）认证配置，内含必填的 `token` 字段。配置后，`/metrics` 与 `/api/*` 的请求必须携带 `Authorization: Bearer <token>`；`/health/live` 与 `/health/ready` 不受保护。              | -                | 否       |

Admin 服务器暴露的端点：

- `GET /health/live`：存活探针，仅反映进程存活状态；只要进程在运行即返回正常，不检查上游健康，也不受 `auth` 保护。
- `GET /health/ready`：就绪探针，附带各上游组的健康信息；当任一上游组存在服务器但健康数为 `0` 时返回 `503`；未触发 `503` 但存在并非全部服务器健康的上游组时，返回 `200` 且状态为 `degraded`。不受 `auth` 保护。
- `GET /metrics`：Prometheus 指标。
- `POST /api/cache/clear`：清空缓存。
- `GET /api/cache/dump`：导出缓存快照。
- `POST /api/cache/restore`：恢复缓存快照。
- `GET /api/upstreams`：查询上游组健康状态。
- `GET /api/routes`：查询当前生效的路由规则。
- `GET /api/info`：查询运行时信息（版本、启动时间等）。

> ✨ **专家提示**：
> 将 `admin` 服务与 `server` 服务分离是推荐的安全实践。你可以将 `server` 的端口（如 53）暴露给局域网或公网，而将 `admin` 的端口（如 9000）只暴露给内部的监控系统，或用防火墙规则严格控制访问。
