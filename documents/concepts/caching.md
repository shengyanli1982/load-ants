# 高性能缓存机制

缓存是 Load Ants 实现高性能、低延迟 DNS 解析的“秘密武器”。启用缓存后，Load Ants 会将曾查询过的 DNS 记录在本地保存一段时间，从而大幅提升重复访问的响应速度。

### 一个类比：大脑的“短期记忆”

你可以将 Load Ants 的缓存机制想象成我们大脑的短期记忆功能：

- **没有缓存**：就像一个记性很差的人。每次朋友问你“小明的电话是多少？”，你都得去翻又厚又重的电话本（查询上游解析器）。这显然很慢。
- **有缓存**：就像一个记性好的人。当朋友第一次问你“小明的电话是多少？”时，你认真地查了电话本并告诉了他。在接下来的一段时间里，如果再有人问起，你就能凭着“短期记忆”立刻回答，而无需再次翻阅电话本。

Load Ants 的缓存就是这个“短期记忆”。它存储了近期 DNS 查询的结果，当相同的查询再次到来时，Load Ants 可以直接从缓存中返回答案，省去与上游服务器之间耗时的网络通信。

这里对“相同的查询”有两点补充说明：

- 缓存键会包含查询携带的 ECS（EDNS Client Subnet）子网信息（如有）：携带不同 ECS 子网的查询会命中各自独立的缓存条目，不会互相串用解析视图。
- 对于缓存的 A/AAAA 应答，Load Ants 会在每次命中时打乱记录顺序，避免所有客户端总是使用同一条首选记录。

### 缓存的两种类型

Load Ants 的“记忆”能力分为两种：

1.  **正向缓存（Positive Caching）**
    - **是什么**：记住那些“成功”的查询结果。例如，记住 `www.google.com` 的 IP 地址是 `142.250.199.196`。
    - **作用**：这是最常见的缓存类型，它能极大地加速对常用网站的访问。

2.  **负向缓存（Negative Caching）**
    - **是什么**：记住“域名不存在或没有对应记录”的结论。例如，记住域名 `non-existent-domain-123.com` 不存在（`NXDOMAIN`），或者某个域名没有所查询类型的记录（`NODATA`）。`SERVFAIL`、`REFUSED`、`FORMERR`、`NOTIMP` 这类错误响应一律不会被缓存，以避免把上游的临时故障固化在缓存里。
    - **作用**：这是一个常被忽视但极其重要的性能优化点。如果没有负向缓存，当你的网络中某个程序或设备持续尝试访问一个不存在的域名时，Load Ants 会不断地向上游服务器发起无效查询，造成不必要的资源浪费和延迟。负向缓存可以有效地终结这种无效的重复查询。

### 理解 TTL（生存时间）

每条 DNS 记录都有一个权威服务器建议的“保质期”，即 TTL（Time-To-Live）。Load Ants 的缓存配置让你直接干预这个“保质期”，强制执行你自己的缓存策略。

- **`min_ttl`（最小生存时间）**
    - **用途**：强制延长那些“保质期”过短的记录。
    - **场景**：某些大型网站为了精细调度流量，会设置非常短的 TTL（例如 60 秒）。这意味着你需要每分钟都去查询一次。将 `min_ttl` 调高（例如设为 `300` 秒），可以强制 Load Ants 将这条记录在缓存中保留至少 5 分钟，从而减少不必要的查询。

- **`max_ttl`（最大生存时间）**
    - **用途**：强制缩短那些“保质期”过长的记录。
    - **场景**：有些域名的 TTL 长达一天甚至更久。如果你希望及时跟上该域名的 IP 地址变更，可以将 `max_ttl` 调低（例如设为 `3600` 秒），强制缓存条目在一小时后过期，并重新向上游查询。

- **`negative_ttl`（负向缓存生存时间）**
    - **用途**：专门为“失败”的查询结果（如域名不存在）设定一个缓存时间。
    - **场景**：这是负向缓存的核心配置。设置一个合理的 `negative_ttl`（例如 `300` 秒）意味着在 5 分钟内，所有对同一个不存在域名的查询都会被 Load Ants 直接从缓存拦截，并立即返回“不存在”的响应，而不会去打扰上游服务器。

- **`stale_while_revalidate`（过期宽限期，stale-while-revalidate 机制）**
    - **用途**：为已过期的缓存条目提供一段宽限期。默认 `0`（关闭）；设为正数后，刚过期的条目可以继续“应急”使用。
    - **场景**：当某个条目已经过期但仍在宽限期内时，Load Ants 会立即返回这条旧记录（该应答中的 TTL 会被修正为剩余时间），同时触发一次后台刷新去上游获取最新结果并更新缓存。这样即使上游响应变慢，查询也不必等待上游。

> 注意：正向应答中只要有记录的 TTL 为 `0`，整个应答就不会被缓存（这是 RFC 2308 中“TTL=0 表示不得缓存”的约定），`min_ttl` 在这种情况下也不会生效。

调整这些 TTL 设置，就能让 Load Ants 的缓存行为贴合你的网络环境和性能需求。
